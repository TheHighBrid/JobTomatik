## At the start of each engineering task

1. Fetch `origin/main`, record exact SHA and dirty-tree status. Inspect `AGENTS.md`, `docs/operations/AI_COOPERATION_BOARD.md`, latest GitHub issue #252 comments, open PRs and affected files.
2. Classify claims precisely: **source implemented**, **test proven**, **physical-runtime proven**, **deployed**, **employer confirmed**; also label unknown and unresolved. Do not treat any of these as synonyms.
3. Check whether a contributor already claims the task or files. Make a **new comment** on #252 specifying your task, branch `antigravity/<slug>`, base SHA, file paths, exclusions, risks, acceptance commands and overlap. If posting is unavailable, draft the exact comment and avoid conflicting edits.
4. Pick the most direct unclaimed dependency. Avoid duplicating #720 durable-preparation integration, #721 offline Settings recovery, #722 Android HTTPS build bootstrap, or any newly claimed follow-on work until the latest issue and PR heads have been checked.

## Engineering loop

- Reproduce the actual defect in a faithful isolated environment. Determine root cause first; preserve unaffected behavior.
- One branch per mission; one agent writes the branch. Use a focused PR and independent review before integration. Do not push directly to protected `main`.
- Favor end-to-end acceptance and negative-path proofs for the affected contract: API ownership/auth, queue dispatch, persistent profile, handoff, outcome evidence, release flags, duplicate prevention and recovery as appropriate.
- Validate on **exact head**, note actual command, result, SHA, Docker image/runtime and timestamps. Follow up on CI failures rather than dismissing them. Keep synthetic proof explicitly synthetic.
- Do not broaden scope into a redesign, unnecessary model migration, cosmetic cleanup, unverified provider switch or paid infrastructure.
- Respect remote/computer tool restrictions; a blocked action is not permission to evade the control. Work on the best independently allowed route.
- Report every deliverable with head SHA, diff/PR, test outputs, artifact paths/hashes, preserved invariants, blocker and next action. No false progress or fake CI green.

## Human gate: stop and preserve

No autonomous final submission to a real employer without **the exact current owner-approved target/payload and effective release-control gates**. No rerequest or replay when outcome is unknown. Never click a final real submit to test a form or turn release flags on merely to pass a check. Do not send recruiter messages or follow-ups without applicable authorization. Never infer legal, demographic, consent, disability, veteran, work authorization, immigration/sponsorship, identity or other personal answers. Never bypass third-party security boundaries, CAPTCHA, MFA, identity proof or assessments. Keep secure resumable handoff and exact target/payload binding. No irreversible production changes, paid commitments or secrets exposure without authorization.

The owner's time is scarce. Do not ask them to rerun repeated shell commands or inspect logs for us. Use existing connected access, tests, local disposable fixtures, CI and safe read-only inspection. Request only a genuinely unavoidable decision/action, once, with exact evidence.
